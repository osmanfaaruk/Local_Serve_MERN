1. Introduction

LocalServe is a web-based directory platform designed to connect skilled professionals and residents in Chittagong. In metropolitan areas, finding reliable services like home maintenance or consulting often relies on word-of-mouth. LocalServe addresses these challenges by providing a platform where quality help is accessible with just a few clicks.

Using a modern tech stack (MongoDB, Express.js, and Node.js), the website helps residents search for verified professionals while allowing service providers to show their expertise and clear pricing. The project aims to make it easier to find help through search filters, keep service costs clear, and build trust through a strict admin-led verification system. Overall, LocalServe modernizes the local service industry in Chittagong, making it easier for professionals to connect with the community.

User Roles & System Segmentation

The platform categorizes users into three primary segments to ensure a secure and structured service flow:

  • 1. General Users (Service Seekers): Consumers who use the platform to find local professionals. They can search by service category and location in Chittagong and view detailed provider profiles without a complex registration process.
  • 2. Professional Service Providers: Skilled individuals or companies who list their services. To maintain quality, they must register and submit a detailed application form. Profiles remain "Under Review" and are only visible to the public after Admin verification.
  • 3. System Administrators: Admins manage the platform via a secure dashboard. They are responsible for reviewing provider applications (Approve/Reject) and managing system data like Categories, Locations, and user accounts.

2. Frontend Implementation

The frontend is split into two parts the Public/Provider Website and the Admin Dashboard.

Technologies & Libraries Used:

  • HTML5 & CSS3: For structured markup and custom styling overrides.
  • Tailwind CSS: Used as the utility-first CSS framework (via CDN) to create custom layouts without writing traditional CSS files.
  • DaisyUI: A Tailwind-based component library that provides pre-styled semantic elements like buttons, cards, badges, and modals.
  • Vanilla JavaScript (ES6+): Handles all client-side logic, including DOM manipulation, API interactions using the fetch() API, and state management.
  • FontAwesome (v6.4.0): Used for vector icons to improve visual context in navigation and dashboards.
  • SweetAlert2 (v11): Integrated for professional popup feedback during critical actions (e.g., successful login, provider application submission).

Public & Provider Website Pages:

  • Home (index.html): The main landing page where users can search for local professionals using category and location filters.
  • Search Results (search-providers.html): Displays a dynamic list of service providers that match the user's search criteria.
  • Provider Details (provider-details.html): Shows the full profile of a professional, including their experience, pricing, and services.
  • Login (user-provider/login.html): A secure page for users and providers to sign in to their accounts.
  • Registration (user-provider/register.html): Allows new users and potential providers to create an account on the platform.
  • Provider Application (user-provider/form.html): A multi-step form for professionals to submit their business details for admin review.
  • Provider Dashboard (user-provider/dashboard.html): A private area for professionals to see their approval status and manage their profile.
  • Account Security (user-provider/security.html): A dedicated page for users to update passwords and manage account safety settings.

Admin Dashboard Pages:

  • Admin Login (admin-login.html): A dedicated secure gateway for platform administrators to access the management panel.
  • Dashboard Home (index.html): An overview page showing real-time statistics of providers, users, categories, and locations.
  • Manage Providers (manage-providers.html): The primary tool for admins to review, approve, or reject professional applications.
  • Add Provider (add-provider.html): Allows administrators to manually input and list new service providers into the database.
  • Manage Users (manage-users.html): A complete list and management interface for all registered customer accounts.
  • Manage Categories (manage-categories.html): Allows admins to add or edit service types like Plumbing, Home Repair, etc.
  • Manage Locations (manage-locations.html): Used to manage the list of neighborhoods and areas within Chittagong supported by the platform.
  • System Settings (settings.html): Configuration area for admin profile details and general system preferences.

3. Backend Implementation

The backend serves as the main engine of the LocalServe platform, providing a secure way to manage data and user logins. It is built using Node.js and the Express.js framework, with a modular design to keep the code organized.

Technologies & Packages Used:

  • Node.js & Express.js: The runtime environment and web framework used to build the RESTful API and handle server-side logic.
  • MongoDB & Mongoose: A NoSQL database for flexible data storage, with Mongoose providing a schema-based solution to model application data.
  • JSON Web Token (JWT): Implemented for stateless authentication, allowing the server to verify user and admin identities securely.
  • Bcrypt.js: Used for industry-standard password hashing, ensuring that sensitive user credentials are never stored in plain text.
  • CORS & Dotenv: Essential packages for enabling Cross-Origin Resource Sharing and managing environment variables securely.

4. Database Connection, ER Diagram & Normalization

Database Normalization Principles

While MongoDB is a document-oriented NoSQL database, relational normalization principles (1NF, 2NF, 3NF) were adapted to ensure data integrity and optimize query performance:

  • First Normal Form (1NF) - Atomicity: All schema attributes contain atomic values. Multi-valued attributes such as service categories and coverage areas are managed as structured arrays within the Provider document, ensuring clear data boundaries.
  • Second & Third Normal Form (2NF & 3NF) - Minimizing Redundancy: Instead of monolithic embedding, the architecture utilizes referencing. The User schema maintains a providerId reference to the Provider collection, decoupling authentication from professional profiles. Administrative configurations are isolated in a dedicated AdminConfig collection to prevent transitive dependencies.
